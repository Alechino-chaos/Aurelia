# Aurelia

一个面向学术论文精读的本地桌面 PDF 阅读器。第一版使用 Electron、React、TypeScript 和 PDF.js。

项目文件用途见 [目录说明](docs/README.md)，上传仓库的步骤见 [GitHub 提交说明](docs/github-publishing.md)。克隆源码后按下方“开发运行”安装依赖并启动；已在本机安装的用户可直接双击桌面的 **Aurelia.lnk**。

0.4.2 为安全维护版：升级 Electron 到 44.7.0，修复构建依赖告警；重复双击只唤起同一配置目录的现有窗口，避免多个进程覆盖阅读记录。进一步限制窗口通信、嵌入页面和表单提交。检查范围及验证结果见 [安全检查记录](docs/security-review-0.4.2.md)。升级时请先正常关闭旧版本窗口，再使用当前快捷方式启动。

## 双击启动（已打包）

在 Windows 桌面双击 **Aurelia.lnk**，即可打开独立桌面程序。无需打开终端，也不需要运行开发服务器。安装位置由本机 `.aurelia-install.local.json` 记录；首次安装默认使用 `%LOCALAPPDATA%\Programs\Aurelia\`，也支持自定义目录。关闭终端不会使它退出。

运行 `npm run dist` 后生成 `release/Aurelia-0.4.2-portable.exe`，是供复制到其他电脑使用的 Windows x64 便携版，包含运行时，无需安装 Node.js。构建产物不提交到源码仓库，可单独上传至 GitHub Releases。已安装的本机程序优先使用桌面快捷方式。

## 高亮与批注

选中文字后，在浮动工具栏选择浅黄或浅绿色，再点击 **高亮**；点击 **批注** 则直接开始写笔记。无需配置 AI 即可使用。

0.4.1 修复了逐词高亮之间的白缝：同一行相邻文字的高亮会连接起来，保留选区首尾边界，较大的栏间空白不填充。此前保存的高亮重新打开后也会使用新的显示方式，无需重划。

右侧新增 **批注** 页签，按页码和位置列出本篇批注：

- 点击摘录或 **定位原文** 跳回对应的页面位置，页边的小批注标记可打开对应记录。
- 点击 **编辑／添加笔记** 修改笔记，输入时自动保存；可切换高亮颜色。
- 删除按钮移除该条高亮和笔记；**撤销删除** 可以恢复最后一条删除记录，切换论文后不再保留撤销状态。
- 在批注中点 **问 AI** 会引用原文；收到回答后，可点 **保存到当前批注** 将回答追加到笔记，保留原有内容。

高亮使用实际选中字符的页面相对坐标，支持跨页选区和 PDF 自带的旋转页，缩放、滚动及调整面板宽度后仍随页面对齐。色块不拦截鼠标拖选和复制。高亮和笔记随论文会话保存在本机，切换或重新打开论文自动恢复；原 PDF 文件不被修改，也不会将笔记自动上传到 AI。当前不提供向 PDF 文件写入或导出批注；扫描件仍需要后续 OCR 才能选择文本。

## 划词翻译与 AI 对话

1. 点击右上角齿轮 **AI 服务设置**，填写 API 地址、API Key 和模型名称。支持 OpenAI 兼容的 `/chat/completions` 接口；地址通常以 `/v1` 结尾，也接受完整的 `/chat/completions` 地址。模型 ID 请从服务商获取。本机免鉴权服务可不填 Key。
2. 选择翻译目标语言，点击 **保存并测试**。测试发送一条短消息并消耗少量 API 额度；只想保存时点击 **保存设置**。
3. 在 PDF 中选中文字，点击浮动工具栏的 **翻译**。右侧显示原文、页码与流式译文，可停止、重新翻译或复制。
4. 点击浮动工具栏的 **问 AI** 或右侧的 **提问**，将选区附到输入框。输入问题后按 Enter 发送，Shift+Enter 换行。可继续追问、停止、重试、复制回答或新建对话。

翻译只发送选中文字；对话发送消息、已完成的历史回答与用户主动引用的片段。原 PDF 不上传，不会自动读取整篇论文作为上下文。普通本地阅读不调用 AI。AI 对话、翻译历史与未发送的草稿按论文自动保存到本机，切换论文和重新打开后会恢复。回答与译文支持 Markdown 加粗、标题、列表、引用、表格和代码块；KaTeX 在本地渲染标准美元分隔符或 math 代码块中的公式。复制按钮保留原始回答，便于粘贴到 Markdown 编辑器。用户消息与 PDF 引用仍按原文显示。

### 按论文保存阅读会话

- 重新打开论文后，恢复当前对话、历史译文、引用原文和页码、未发送的草稿及其引用。右侧显示保存状态；保存失败时提供重试。
- **新建对话** 保留旧对话，通过 **对话记录** 下拉框切换。每次翻译都保留一条记录，通过 **翻译记录** 切换。
- 以 PDF 文件内容的 SHA-256 区分论文：同名而内容不同的文件分别保存，改名或移动内容完全相同的文件仍可恢复。修改 PDF 内容后会作为另一篇文档保存。
- 切换论文或正常关闭时，停止仍在生成的请求，保存已收到的部分；恢复后可手动重试。加载历史不会自动调用 API。
- 记录保存在 `%APPDATA%\paperdesk\reading-sessions\`，为本地 JSON 文本，包含对话和引用，不包含 API 配置或 Key。使用临时文件替换及上一次保存的备份，读取损坏文件时保留原件；没有可用备份则提示错误，不用空记录覆盖。
- 生成中的文字约每 200ms 保存一次，正常关闭会等待落盘；强制结束进程或突然断电仍可能损失最后尚未写入的少量内容。单篇会话文件上限为 32MB，达到限制时提示保存失败，不会静默删除历史。
- 0.3.5 之前的记录仅在内存中，无法追溯恢复；首次升级前需要的旧对话请先复制。

Markdown 不执行模型生成的 HTML；外部图片显示替代文字而不自动加载，链接显示文字和地址而不自动打开。公式渲染关闭信任模式并限制宏展开，相关字体随软件打包，不依赖外部 CDN。

API Key 在主进程通过 Electron `safeStorage` 加密保存，不放入 localStorage、不写入项目，也不通过读取设置接口返回明文。Windows 下使用系统 DPAPI；系统加密不可用时拒绝明文落盘。更换 API 服务商域名或端口时必须重新输入对应 Key，或者勾选清除 Key。为兼容改名前的数据，配置仍保存在 `%APPDATA%\paperdesk\ai-settings.json`。此文件不适合复制到其他电脑，换机后应重新填写 Key。

远程服务要求 HTTPS，本机 `localhost` / `127.0.0.1` / `::1` 支持 HTTP。请求由 Electron 主进程发送，使用系统网络代理，不自动跟随重定向。认证失败、额度不足、断流和超时均会显示可重试的错误；单次请求超时为两分钟。翻译上限 30,000 字符，对话请求上限 100,000 字符及 20 轮已完成历史，超过时需缩短选区或新建对话。

兼容性依据：[Chat Completions 接口](https://developers.openai.com/api/reference/resources/chat)、[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。未针对每家服务商逐一实测；仅提供 Responses、Anthropic 原生等其他协议的端点需要兼容网关。

## 开发运行

需要 Node.js 22.13+（推荐 Node.js 24 LTS）与 npm。

```powershell
npm ci
npm run dev
```

打开桌面窗口后，点击“打开 PDF”，或把文件拖入窗口。也可以先点击“体验双栏示例”。

生产构建与启动：

```powershell
npm run build
npm start
```

打包 Windows 便携版：

```powershell
npm run dist
```

产物保存在 `release/`，不纳入版本控制。当前没有配置发布签名或自动更新。`npm run dev:web` 可单独预览界面；浏览器模式使用文件选择器，桌面端的最近文件能力需在 Electron 中使用。

开发者更新本机双击启动版本时，先关闭已安装的软件，执行 `npm run dist`，再在 PowerShell 中执行 `./scripts/install-local.ps1`。脚本沿用本机记录的安装根目录，将构建复制到新的版本目录，并更新桌面快捷方式；不会覆盖源码或删除阅读记录。指定其他磁盘可使用 `./scripts/install-local.ps1 -ApplicationRoot 'E:\Aurelia'`。仅运行 `npm run dev` 不会更新已安装版本。

如果工作区带有 Windows Low 完整性标签，Electron 可能在初始化前退出。可通过 `PAPERDESK_ELECTRON_PATH` 指定普通用户目录中同版本的 Electron 运行时，或使用被 Git 忽略的 `.paperdesk-runtime.local.json`；`npm run dev`、`npm start` 和测试均支持此配置。普通工作区不需要此配置，不应为此关闭应用沙箱。

## 第一版功能

- 本地打开与拖放 PDF，最近文件记录，错误提示，加密 PDF 密码输入。
- 连续滚动、页码跳转、页码侧栏、25%–300% 缩放、适合宽度。
- 可选择文本层；常见双栏论文按左栏、右栏顺序整理，通栏行分隔阅读区域。
- 选区浮动工具条、右侧原文／清理预览，原样复制、清理复制、带文件名和页码复制。
- 可拖动或使用方向键调整的右侧面板，可收起；面板宽度与阅读页码保存于本机。
- 离屏页面释放画布；已访问页面保留文本层；位图按页面像素预算控制内存。

0.2 版新增划词翻译、可引用选区的流式 AI 对话、API 配置和连接测试。全文检索问答尚未接入。

0.3 版采用浅绿桌面布局：合并顶部工具栏，右侧集中显示复制、翻译和提问。展开选区面板中的 **复制选项**，可切换自动分栏／PDF 原始顺序、原样复制、带出处复制及断词处理。文本顺序设置在没有选区时也可使用。旧版保存的面板宽度继续生效；双击分隔条恢复新版默认宽度。

0.3.5 新增按论文保存阅读会话：自动保存对话、译文、引用与草稿，支持历史切换、重启恢复和未完成回答重试。

0.4.1 新增浅黄／浅绿高亮、按论文保存批注、编辑笔记、原文定位、删除撤销与 AI 回答追加到笔记。右侧四个标签统一为 16px，选中项加粗，标签栏适配 280px 窄面板。兼容读取 0.3.5 的已有会话。

0.3.4 优化缩放：缩放中保留并缩放已有画面，停手 150ms 后合并重绘；新倍率的清晰画面完成后再替换旧画面。按实际屏幕像素密度绘制，不再固定限制为 2 倍密度；超出整页预算时使用预览底图加可见区域的原生密度高清分块，滚动后补齐并回收远处分块。可见页优先排队，旧缩放请求取消；文本节点和分栏顺序复用，通过 PDF.js 更新可见页的字符几何。瞬时缩放仍可能短暂略糊，最终画面按新倍率重新渲染；原文件内低分辨率扫描图的细节受源图限制。

0.3.3 修复鼠标进入行尾或行间空白时选区突然扩大到后面多行的问题。文本层增加随拖选终点移动的空白边界保护，沿用浏览器的逐字、正反向和跨行选择；空白处结束的选区也支持清理复制。

0.3.2 新增 AI Markdown 与公式渲染，支持流式更新；同时将 PDF.js 更新至 6.2.108，并统一 KaTeX 至 0.19.0，修复生产依赖检查发现的问题。PDF.js 沿用官方 legacy 构建，文档释放改为通过 loadingTask 完成；双栏选择、缩放与跳页均通过回归检查。

## 双栏选择和复制

PDF 的绘制指令顺序不一定等于阅读顺序。`src/pdf/readingOrder.ts` 按文本坐标分组行，寻找重复出现的中央栏间空白。只有足够多的行提供证据时才分栏；通栏文本将页面切成独立区域，每个区域按左栏、右栏排列。整理后的文本交给 PDF.js 的原生 TextLayer，画布中的原始版式不变。

`src/pdf/selection.ts` 从浏览器选区读取实际选中的字符范围，依据行、段落与页码元数据重建文本。它不会用大模型改写内容，也不执行会改变数学字符的全局 Unicode NFKC 归一化。

默认行为：

- 合并段落内部的换行，保留推断的段落边界。
- 转换常见排版连字，例如 `ﬁ` → `fi`，移除软连字符。
- **保留可见连字符**。例如 `frame-` 换行 `work` 默认复制为 `frame-work`；`state-` 换行 `of-the-art` 保留为 `state-of-the-art`。
- “删除行末断词连字符”是显式选项；开启后 `frame-` 换行 `work` 可合并为 `framework`，但也可能误改复合词，需核对预览。
- 原样复制保留文本层提取的字符和推断行边界，不等于恢复 PDF 文件的底层字节顺序。

### 适用边界

自动分栏是几何启发式，重点支持常见的可提取文本单栏／双栏论文，不能保证任意 PDF 的阅读顺序。多栏杂志、复杂表格、公式、边注、特殊字体、损坏编码和旋转文字请核对预览，必要时切换“PDF 原始顺序”。扫描件可显示，但需要后续 OCR 才能选中文字。跨页文本保留页边界，页眉／页脚不会被自动删除。当前没有旋转按钮、PDF 链接注释层或书签目录。

首次打开时读取页面尺寸，画布只渲染附近页面。PDF 文件本身及解析对象仍占内存，因此第一版限制单文件 250 MB，并非任意大小文件都能保持恒定内存。

## 验证

```powershell
npm run typecheck
npm test
npm run test:e2e
```

- 单元测试验证交错双栏、通栏标题、段落边界、保守断词规则、中文换行与数学符号保留。
- AI 单元测试覆盖中文 UTF-8 分片、SSE、断流、JSON 回退、请求角色与地址校验；桌面测试使用本机模拟服务，验证加密保存、重启恢复、翻译、引用、多轮对话、错误重试、停止、清除 Key 和切换文档取消请求，不调用真实付费 API。
- 会话测试覆盖同名论文隔离、改名恢复、历史对话和译文切换、草稿、关闭期间的流式内容、迟到消息隔离、并发保存、损坏备份恢复和写入失败重试。
- 批注测试覆盖旧会话兼容、几何校验、双栏鼠标选区、高亮后的复制、缩放对齐、窄面板、颜色与删除撤销、原文定位、跨页与旋转页、重启恢复及模拟 AI 回答追加。
- Electron 端到端测试通过本地文件接口打开内置示例，进行真实鼠标正向／反向拖选，读取系统剪贴板，验证局部字符选择、面板调整、缩放、连续滚动、页面跳转与损坏文件处理。
- 测试专用文档由 `node scripts/create-fixtures.mjs` 生成；刻意交错写入左右栏绘制指令。它是合成排版样本，不是学术论文。
- 截图在 `test-results/screenshots/`；测试使用独立的 `tmp/e2e-profile/`，不会覆盖个人阅读记录。
- 若 `tests/fixtures/references/tracemonkey.pdf` 存在，还会验证 Mozilla PDF.js 的真实双栏论文样本；没有该文件时只跳过这一项。可从 `https://mozilla.github.io/pdf.js/web/compressed.tracemonkey-pldi-09.pdf` 下载，样本不随应用发布。

## 目录

```text
electron/                 桌面主进程与隔离的 preload 接口
src/App.tsx               阅读工作区与交互
src/components/PdfPage.tsx 页面渲染及文本层生命周期
src/pdf/                  PDF 引擎、阅读顺序和复制处理
scripts/                  开发启动、离线资源准备、测试样本生成
tests/                    单元与 Electron 端到端测试
tests/fixtures/references/ 可选的真实论文测试样本
public/examples/          内置双栏示例
designs/                  本地设计档案（不提交）
docs/                     目录与项目维护说明
release/                  打包生成的程序（不提交）
```

PDF.js Worker、CMap、标准字体与 WASM 随应用打包，阅读不依赖 CDN。原 PDF 不会被修改或上传；主动使用 AI 时会发送上述文字内容。最近文件列表保存在 Electron 用户数据目录；阅读位置与面板宽度保存在应用本地存储中。渲染进程启用沙箱和上下文隔离，preload 只暴露文件打开、最近文件、剪贴板和受校验的 AI 接口。

PDF.js 使用官方 `legacy` 兼容构建及对应 Worker；Electron 与其他依赖的实际安装版本由 `package-lock.json` 固定。

若网络环境要求代理，安装 Electron 二进制时可配置 `ELECTRON_GET_USE_PROXY=1` 和 `GLOBAL_AGENT_HTTP_PROXY`，然后重新运行 `npm install`。不要把代理凭据或 API 密钥写入仓库。
