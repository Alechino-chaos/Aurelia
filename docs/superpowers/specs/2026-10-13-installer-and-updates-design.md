# Aurelia 安装版与应用内更新设计

日期：2026-10-13
状态：已获用户批准并完成实现、本机安装和隔离升级验证；尚未发布 GitHub Release。
交付版本：0.10.0。

## 1. 目标与已确认需求

让普通用户首次安装 Aurelia 后，能够在软件里完成后续版本升级，无需每次寻找 GitHub 下载页面、替换 exe 或重建快捷方式。

用户已明确确认：

- 从免安装便携版改成 Windows 安装版。
- 启动后自动检查更新，但只有用户点击“下载更新”才下载。
- 用户点击“重启并更新”后才安装；普通退出不触发安装。
- 首次安装默认位置已经选好，也允许用户修改安装位置。
- **首次打开安装包的首屏必须明确提供“自定义安装”入口。** 仅在后续页面提供目录输入框，不满足此要求。
- 沿用中英文界面；保护现有论文、批注、阅读记录、语言和 AI 设置。

下文中的界面位置、检查频率、失败处理、默认安装范围等是推荐设计，随本文件一起审阅。

## 2. 方案选择

| 方案 | 特点 | 结论 |
| --- | --- | --- |
| NSIS 安装版 + electron-updater + GitHub Releases | 复用现有 Electron 打包体系，支持下载进度、安装升级与 GitHub 分发 | 采用 |
| 保留便携版并自写替换程序 | 需要自行处理启动器、文件占用、权限与替换失败 | 不采用 |
| 仅提示并跳转下载页 | 实现较少，但仍要求用户手动完成每次更新 | 不符合本次目标 |

继续使用现有 Electron、React 和 TypeScript。保留当前 electron-builder 26.x 系列，选择与其兼容的 electron-updater；本任务不顺带升级 Electron 或打包工具的大版本。

用成熟更新组件管理下载安装，自定义 Aurelia 的提示界面和保存后重启流程。

## 3. 首次安装体验

### 3.1 安装包首屏

使用 Aurelia 原图标和名称。首屏显示版本、默认安装路径，并同时提供：

| 控件 | 行为 |
| --- | --- |
| 立即安装 / Install | 使用显示的默认路径和默认快捷方式选项开始安装 |
| 自定义安装 / Custom installation | 进入自定义页面，修改路径和快捷方式选项；点击本身不开始安装 |
| 取消 / Cancel | 退出安装，不安装软件 |

“自定义安装”必须可见、可通过键盘访问，与“立即安装”处于同一首屏；不能藏在菜单、齿轮或默认折叠的高级设置中。

首屏采用 NSIS 自定义欢迎页完成。安装、卸载和自动升级主体仍使用 electron-builder 的安装模板，避免维护整套自制安装器。

### 3.2 自定义安装页

- 显示预填的安装路径，提供“浏览”和“恢复默认位置”。
- 显示所需空间和选定磁盘的可用空间。
- 提供“创建桌面快捷方式”选项，默认勾选；创建开始菜单入口。
- 提供“返回”和“开始安装”。
- 支持中文、空格路径及其他本地盘符；不可写路径、系统目录、磁盘根目录或明显危险的目标应给出可理解的错误。
- 选定目录作为 Aurelia 的专用程序目录，不扫描或删除该目录以外的内容；存在无关文件时不直接覆盖。

默认仅为当前 Windows 用户安装，默认位置为该用户的本地应用程序目录下的 Aurelia。允许选择 D 盘等可写目录；第一版不增加“为所有用户安装”，以减少管理员权限和后续升级的复杂度。

安装器按系统语言初选中文或英文，并允许切换。安装器的语言不会代替应用内首次语言确认，也不改变翻译目标语言。

### 3.3 安装完成与后续升级

- 完成页提供“启动 Aurelia”。
- 首次安装允许选择位置；后续应用内更新沿用原位置，不重新询问路径或恢复用户取消的快捷方式。
- 自定义页面只用于交互式安装，应用内升级使用静默更新路径，不停在欢迎页。
- 应用数据继续保存在用户数据目录，与程序目录分离；换安装盘不会移动原始 PDF。
- 卸载第一版默认保留用户资料；不附带默认勾选的数据清理行为。

## 4. 应用内更新体验

### 4.1 检查与入口

- 在首次语言选择完成、工作区可用后，延迟约 10 秒进行后台检查。
- 自动检查最多每 24 小时一次；长时间运行时，到期且窗口重新获得焦点再检查。
- 手动“检查更新”不受 24 小时限制，但同一时间只允许一个检查任务，重复点击合并。
- 设置新增“关于与更新”页面：当前版本、检查状态、最后检查时间、更新摘要和对应操作。
- 通用设置提供“启动时自动检查更新”开关，默认开启；关闭后手动检查仍可用。

### 4.2 提示与下载

- 发现新版，在窗口右上角显示不抢焦点的轻提示：新版本号、“查看更新”和“稍后”。
- 提示不依赖阅读工具栏是否显示；隐藏工具栏时仍可找到更新入口。
- “查看更新”打开“关于与更新”，展示版本和摘要，以及“下载更新”按钮。
- “稍后”只关闭当前提示；当前运行期间不反复弹同一版本，设置中仍能操作。
- 点击“下载更新”后才请求安装包数据，显示百分比、已下载量和“取消下载”。
- 下载期间可继续阅读、做批注和操作 AI；不会抢占右侧阅读助手。
- 下载完成后显示“重启并更新”和“稍后”。
- 关闭软件或下次启动均不自动安装；已下载且仍有效的更新可以再次提示用户主动安装。
- 更新界面文本随界面语言切换；GitHub 发布说明继续用英文，原样展示安全处理后的摘要，不调用 AI 翻译。

### 4.3 状态与恢复

| 状态 | 用户可见行为 |
| --- | --- |
| 未检查 / 检查中 | 显示当前版本及检查状态，避免重复任务 |
| 已是最新 | 手动检查时明确反馈；自动检查无需打扰 |
| 有新版 | 展示版本、摘要及下载按钮 |
| 下载中 | 显示进度，可取消 |
| 下载已取消 | 可重新下载，不承诺跨进程断点续传 |
| 可安装 | 显示“重启并更新”，允许稍后 |
| 正在保存 | 暂停重复更新操作，等待阅读状态落盘 |
| 检查或下载失败 | 显示简短原因、重试及官方发布页入口；当前版本继续可用 |
| 保存失败 | 保持应用打开，不启动安装器；提供重试或取消更新 |

检查超时、GitHub 暂时不可达或请求受限，都不能阻塞启动和阅读。不得把网络失败显示成“已是最新”。不检查预发布版本，不自动降级，不并行下载多个版本。

## 5. 重启与数据保护

现有 electron/main.ts 已有关闭前抓取阅读状态、SessionStore.close() 和 LibraryStore.flush()；更新流程必须复用并补齐这些步骤，不能直接调用更新组件退出而绕过保存。

建议顺序：

1. 验证已下载安装包和当前更新状态仍有效。
2. 若 AI 正在生成，提示“停止生成并更新 / 继续阅读”；取消时保持原状态。
3. 暂时阻止新的编辑与 AI 请求，停止并等待已有生成请求收尾，保留已接收内容和中断状态。
4. 抓取当前论文、页面、缩放、打开的论文及已有草稿恢复机制管理的状态。
5. 等待批注、会话、论文库、语言及 AI 配置写入结束；任何失败均恢复可操作状态并暂停更新。
6. 成功后进入一次性的安装退出流程，避免关闭事件循环或重复安装。
7. 新版本启动时恢复正常工作区与语言，不再次弹首次语言选择。

不新增“保存失败也强行更新”。更新失败恢复交互时，已停止的 AI 请求保留为中断状态，由用户选择是否重新生成。

安装中断、磁盘故障或断电不能保证自动回滚。第一版提供重新运行官方安装包的修复路径，并要求用户数据目录始终不被安装器删除；不宣传尚未验证的自动回滚能力。

## 6. 旧便携版与本机开发安装的迁移

- 旧版没有更新检查器，因此用户需要手动下载并运行首次安装版一次。
- 保持 appId、应用名称和现有 `%APPDATA%\paperdesk` 数据位置，沿用既有数据格式。
- 同一 Windows 用户下验证语言、论文库分组、阅读位置、批注、AI 配置和加密 Key 可继续使用。
- 老应用正在运行时提示正常关闭并等待保存；不强制结束，不允许安装时存在另一个写同一资料目录的旧进程。
- 首次安装完成后，从新的快捷方式启动；提示旧便携 exe 可由用户自行删除，不自动搜索磁盘并删除。
- 本机此前使用的 E:\Aurelia 时间戳目录属于开发交付方式，不应假装成 NSIS 已安装记录。
- 本机转入真正的安装版后，交付脚本读取安装器登记的实际目录并验证；停止每次生成新目录并手工指向它的方式。
- 用户此前清除过的数据不属于迁移可恢复范围。

## 7. 技术边界与模块

| 部分 | 责任 |
| --- | --- |
| NSIS 配置与自定义欢迎页 | 安装首屏、目录选择、快捷方式、卸载、静默升级 |
| 主进程更新服务 | 唯一更新任务、检查节流、版本判断、下载状态与取消、安装前校验 |
| 更新偏好存储 | 独立保存自动检查设置和检查时间，原子写入，不影响语言设置文件 |
| 保存与退出协调器 | 等待请求收尾和持久化，成功后才交给安装器 |
| preload 的窄接口 | 获取状态、订阅状态、检查、下载、取消、重启更新；不接收任意 URL 或执行路径 |
| 设置和提示组件 | 渲染状态、进度、摘要及按钮，保持中英文和键盘可访问性 |
| 发布流程 | 产出同一构建的安装包与更新元数据，上传完整后发布 |

现有语言设置校验要求只含 locale，不能直接加入更新字段；更新偏好使用独立文件。主进程是更新状态的唯一权威，渲染层不能指定下载安装其他程序。

仅信任固定的 Aurelia 官方 GitHub 仓库，使用 HTTPS、更新组件的完整性检查及已配置的签名验证。GitHub 的下载重定向由官方 provider 处理；远程发布说明作为不可信内容渲染，禁用 HTML、脚本和危险链接。

应用中不存放 GitHub 发布 Token；公开仓库的普通用户无需配置账号。发布凭据仅存在发布环境中。第一版不引入付费证书购买或自动改动系统安全设置，未签名安装包的 Windows 提示不伪装成已解决；后续配置代码签名时明确绑定发布者并测试升级链路。

设置 electron-updater 为用户触发下载、用户触发安装，关闭 autoDownload 和 autoInstallOnAppQuit。开发环境不连接生产自动更新源；便携残留或未登记的开发安装不执行安装版的自动升级路径。

## 8. 打包与发布

- Windows x64，使用完整离线安装包，下载后首次安装无需再获取应用主体。
- 安装包命名建议：`Aurelia-0.10.0-setup.exe`。
- GitHub Releases 继续作为分发渠道，标题和发布说明使用英文。
- 从此发布安装 exe 和自动更新必需的 `latest.yml`，并上传构建产生且更新流程需要的 `.blockmap`。
- 不额外上传供用户手动使用的 `.sha256` 文件。更新元数据是程序所需内容，不要求用户下载或操作。
- 不再将“仅上传便携 exe”作为新版本规则；用户已选择的安装版路线取代旧规则。实施时同步更新 AGENTS.md、README 和交付脚本。
- 在草稿 Release 中上传同一构建的全部附件并核对，全部准备好后再公开。不能混用不同构建的安装包和元数据。
- 正式稳定版本使用严格递增的版本号。应用内比较实际运行版本，不能把本机较新的开发版降到 GitHub 的旧版本。
- 此设计不授权现在发布 Release；真实发布仍遵循用户当次发布指令。

## 9. 验收标准

### 安装体验

- 首次运行安装包，在同一首屏看见“立即安装”和“自定义安装”，鼠标与键盘均可操作。
- 默认路径安装、自定义 D 盘目录、中文和空格路径均成功。
- 取消自定义页和取消安装不会意外开始安装或清理既有数据。
- 不可写目录、空间不足、旧程序正在运行均有清楚提示。
- 安装完成后的快捷方式、安装登记、程序真实版本一致；卸载入口可用。

### 更新体验

- 自动检查不下载安装包；点击下载后才出现安装包网络请求。
- 有新版、最新、离线、超时、请求受限、取消、下载损坏均有对应状态。
- 关闭软件、重新启动、点击“稍后”均不会自行安装。
- 双击按钮、重复窗口事件、取消后迟到的下载事件不引发重复下载或安装。
- 中英文、窄窗口、不同系统缩放下提示与进度均可用，隐藏工具栏也能进入更新页。

### 数据与真实升级

- 用隔离 Windows 用户或虚拟机验证旧便携版迁移和安装版 A → 安装版 B 的真实升级。
- 在真实 NSIS 安装目录执行测试，不以解包 exe 或开发窗口代替安装验证。
- 覆盖默认路径和自定义路径升级，升级后路径与快捷方式偏好保持。
- 检查批注、阅读位置、语言、分组和 AI 设置保留；AI 生成中更新需确认停止。
- 模拟保存失败，证明安装器没有启动、原应用仍可继续使用。
- 模拟下载失败和安装中断，验证用户数据仍保留，并演练重新运行安装包的修复路径。
- 运行现有单元测试、类型检查、语言回归与阅读功能冒烟测试。
- 网络验证先使用隔离更新源；如需 GitHub 端到端验证，使用明确隔离的测试发布，避免向正式用户推送测试版本。

## 10. 范围与后续步骤

本次实现 Windows 安装、迁移、稳定版本检查、手动触发下载与安装、可靠保存和发布配套。暂不加入 macOS/Linux 安装器、测试版频道、自有下载服务器、自动降级或自动回滚。

已按实施计划完成安装器、更新协调器、双语界面和本机交付。默认目录及中文自定义目录的真实 A → B 升级、重启后恢复和中断安装修复已通过隔离测试。公开更新源的端到端分发需在正式发布对应安装包和元数据后验证。
